# 模组简介

《植物大战僵尸杂交版》的托管 C# Mod，把游戏各界面的背景音乐换成玩家自己放的歌。

- 适用游戏版本：《植物大战僵尸杂交版》`0.31.0.0`
- 引擎版本：Godot `4.7.0`（.NET 版）
- .NET 目标框架 `net9.0`，所需 SDK `9.0` 及以上
- 模组版本：`1.3.0`
- 模组作者：百合小希

**模组包内不携带任何音频文件。** 运行时从模组指定的目录读取，换歌、加歌都不用重启游戏（个别情形仍需重启，原因见「怎么用」第 4 条）。

**关于开发方式**：本模组的代码与文档在 ChatGPT6.1-Sol 的协助下完成，所有内容均由 AI 参与制作与审阅。仓库内就是完整源码，有疑问请联系我本人，虚心听劝。

## 这个模组能做什么

- **界面音乐替换**：主菜单、商店弹窗、选关、图鉴各有一个下拉框，在游戏的「Mod 管理 → 音乐盒 → 配置」里选。每组第一项是总开关，关掉后整组回到游戏原声。
- **按文件名成曲**：`存档目录\Seeleyuwo\rez\BGM\` 里（含任意深度的子文件夹）每个音频文件都是一首可选曲目，曲名即文件名。
- **战斗 BGM 覆盖**：文件名正好是游戏里某首战斗背景音乐的曲名（共 13 首）时，自动替换那一首，不用在面板里选。
- **换文件不用重启**：模组每秒核对一次目录指纹，有变化当场重载，正在播的界面也会换曲。
- **续播**：从载入界面进主菜单、选关、图鉴时不再从头重播，接着刚才的位置播。
- **格式预检**：游戏读不了的歌（超 64MB、24-bit FLAC 等）不会出现在下拉里，日志会写明是哪一首、什么原因、该转成什么格式。格式按**文件头**识别，所以「文件名是 .mp3、内容其实是 FLAC」这种挂错名的歌也能正常播。

本模组只接管背景音乐：**战斗报幕音和游戏音效一律保持原版**，不读取、不接管任何音效目录。

## 怎么用

1. 把音频放进 `存档目录\Seeleyuwo\rez\BGM\`，即 `%APPDATA%\Godot\app_userdata\植物大战僵尸杂交版\Seeleyuwo\rez\BGM\`，可以自己建子文件夹分类。
2. 选项 → Mod 管理 → 音乐盒 → 配置，四个界面各选一首。
3. 支持的格式：wav / ogg / mp3 / **16-bit 立体声** FLAC，单个文件不超过 64MB。游戏没有解码器的格式读不了——24-bit FLAC、5.1 声道、wma / m4a / aac 都属于这一类，转成 ogg 或 mp3 最省事（`ffmpeg -i 输入 -vn -ac 2 -c:a libmp3lame -q:a 0 输出.mp3`）。
4. 新歌**播放**不用重启，但要出现在下拉里得重启一次游戏：下拉选项存在安装包内，模组重启时会把声明重写成目录实际扫到的曲目。

## 非战斗场景圆形播放器（开发测试）

- 覆盖游戏当前已识别的非战斗界面：主菜单、选关、自制关卡（列表/编辑）、独立结算，以及主菜单下的商店/图鉴。选卡属于 TowerDefense 战斗流程，播放器从进入该场景起隐藏；沙盒、加载和未知的第三方自定义场景也默认隐藏。
- 使用初始化时预建的运行时子作用域托管单个视口浮层，切场景时释放旧音乐控制、切换到对应配置，不会叠加新播放器。商店/图鉴的浮层在其原生界面之上；打开嵌套模态弹窗后退到模态层后方并禁止操作，音乐不中断。
- 播放器没有鼠标悬停提示，歌曲状态和保存错误仍显示在组件正文或日志里。
- 播放器鼠标操作期间，临时屏蔽原生 DragMenu 的早期全局鼠标轮询，清理残留 mousePress，并恢复各菜单原有的输入开关。不全局清除鼠标动作，不修改宿主脚本，组件外的原生输入照常接收。
- 屏蔽/恢复用真实 DragMenu 与视口路由验证过。合成输入不会移动操作系统光标，所以实际鼠标驱动的背景位移还没有验收。
- 切场景开始即进入等待状态，目标节点 Ready 且宿主音乐已启动后再绑定。宿主 StopAll 时清空、回收、重建播放器并自动同步自身资源刷新，不再误报为永久接管。
- 同一本地文件及缓存版本在非战斗界面之间恢复进度或主动暂停；不同歌曲不沿用旧位置；进入战斗会丢弃续播意图。来源不明的改动仍让出控制，可点击播放按当前配置重新同步。
- 还重放了原生 AudioStopAll、节点 QueueFree、新根节点 Ready 与原生 AudioPlay 的顺序，以及加载标记尚未置位的窗口。这些都不等于在完整游戏里把所有场景都过一遍的实机验收。
- 非主界面的普通浮层高于原生第 10 层前景按钮，修掉了「看得见但点不到」。图鉴暂停场景树时播放器仍可操作，不把引擎自动暂停当作用户主动暂停。
- Mod 配置 → 播放器新增「悬浮窗置顶（游戏内）」，默认关闭，保存后即时生效，不重载音乐。开启后优先于一般浮层；确认弹窗仍优先；不会置顶到操作系统桌面，也不改变战斗隐藏规则。
- 原来的「重置位置」按钮换成了播放顺序选择，并与原生配置同步：顺序/倒序到列表边界停止；乱序多首时不连续重复同一首；循环则在列表首尾衔接。自动切歌只用于已选中的本地曲目，原版音乐仍按宿主的方式播放。
- 列表播放使用独立的非循环音频资源和自然结束信号，不改共享缓存音频的循环属性；离场和旧回调失效后不再自动切歌。
- 圆形唱片原地扩展为同一个圆角播放器，过渡约 200ms。收起态 124×124，展开态 336×264；收起态直接支持上一首、播放/暂停、下一首。点击中央独立按钮暂停或继续，单击空白主体在松开时展开，展开态点收起按钮或主体收回。
- 按住主体区域的左键即可拖动，越过系统拖动容差后即时跟随，不设长按倒计时，也不对拖动做缓动。按钮、曲库、滑块独立响应，不会拖动组件。松开保存位置；失焦、Escape、弹窗或离场都会取消未提交的移动。中键和右键不触发组件操作。
- 在 Mod 配置 → 播放器中切换「显示非战斗场景悬浮播放器」，可即时隐藏/显示，曲目、音量与暂停状态保留；重新显示时默认收起。
- 选曲和前后切歌保存到当前界面对应的原生配置。新增「自制关卡界面音乐」「结算界面音乐」，与主菜单、选关、商店、图鉴彼此独立。选择歌曲会开启该配置所属组；原版选项保存为不替换，其他界面的曲目值不改写。
- 使用公开的配置编辑器与安装包中已同步的曲目声明；保存失败不切歌，并显示失败原因。不另写第二份曲目偏好，也不直接覆盖原生配置文件。原生面板改动后播放器同步读取。
- 音量与暂停只控制当前上下文的音乐播放器，不改全局音乐总线。图鉴的 ChooseYourSeeds、自制关卡/选关/结算共用的 ZenGarden 均按界面范围替换，离开时还原。
- 使用 Runtime API v3 的 Lifetime 子作用域和 Data.Local，不依赖只有主菜单才发出的展示挂载事件。未提供这些 API 的旧宿主不在适配范围内。进度依赖可用时长，拿不到就禁用拖动。
- `1.3.0-beta.2` 符合 SemVer：预发布版本低于同号的 `1.3.0`，不是 `1.3.0.1`，也不是构建元数据。

发版验证：编译 0 警告 0 错误；SemVer、22 项托管回归、合法/坏包退出码及 49 项包检查通过。新增的曲目索引回归覆盖空库、缺失、首尾和空选择；包闸门禁止重新引入发行裁剪运行库缺失的 FindIndex 引用。在隔离的 Godot 4.7 窗口中用实际宿主程序集运行 163 项播放器检查，全部通过（含按场景保存、共享键还原、战斗/沙盒排除、真实作用域冻结后挂载和清理，以及对照原生 100 层的商店输入路由和嵌套模态优先级）。场景夹具用相应宿主类型的子类屏蔽宿主资源初始化，因此不等同于完整游戏场景实测。测试夹具退出时仍有未入树管理器/资源清理警告，不能当作模组无泄漏的证明。未做完整游戏内试用、系统鼠标拖动、跨进程位置恢复及实际听感验收。

可用构建参数 `--runtime-dir` 指向实际发行运行库，增加只读元数据检查。该检查按实际程序集及类型转发链解析框架类型，并比较直接方法的名称、泛型元数和参数数；不覆盖所有泛型实例、完整签名或运行时行为，不能替代发行版实测。之前出过故障的旧包能被拒绝，原因是 System.Runtime 缺少 EntryPointNotFoundException 转发。

## 维护要点与 API 边界

维护时参考的是游戏源码提交 `a6b0b939dd`（本地）和[官方模板](https://github.com/axh-xecoy/pvzhe-mod-template/tree/2b0238d)里的生命周期、设置与音频说明。模板的业务代码和游戏资源都没有复制过来。

- 新的商店音频键在 `Initialize` 中用 `context.TryRegister` 预注册；初始化后注册表冻结，切歌只更新已有流。
- 初始化期间向 `context.Lifetime` 登记幂等清理；卸载时取消定时器、解绑事件，并恢复仍由本模组持有的音频。
- 统一更新服务在初始化时取得，上报后检查异步回执；只有确认无更新的成功回执才调用 `ReportUpToDateAsync`。为兼容缺少 Updates 的旧发行，仅这一处边界保留反射适配。
- 原生设置继续使用 `Settings.Get<T>` / `Settings.Changed`；旧构建的落盘兼容读取同时校验 `version=1` 和 `modId`。文件损坏时不会清掉上一份有效副本。
- **仍有限制**：当前设置 API 没有公开的运行时下拉选项更新入口，因此只能回写包内声明，供下一次启动读取。它可能改变安装包哈希，使宿主要求重启。没有用反射改写宿主私有设置字段。
- 目录变化需连续两次扫描稳定后才提交；相同歌曲按路径、大小和修改时间缓存。逐曲注册、播放器刷新及逐帧续播日志已移除，保留启动摘要、配置实际变更和去重后的错误。

离线回归覆盖 SemVer、配置/目录指纹以及合法包/坏包的退出码。**这些测试不能替代游戏内验收**：主菜单、商店进出、选关、图鉴、暂停、切歌、禁用卸载和实际听感都得实机确认，所以开头声明的适用游戏版本没有跟着这些测试一起扩大。

## 显示范围边界与待确认事项

- 图示的墓碑选项面板由游戏 MenuDialogBase / DialogMainMenuOption 和原生 MainButton 生成。音乐盒没有改动这些节点或全局主题；具体是哪个控件错位还得用户指一下。光看截图既不能断定是本模组造成的，也不能说已经修好。

## 构建与打包

需要 **.NET SDK**，版本要求见开头「模组简介」里的 .NET 目标框架：三个工程的目标框架都用它，同系列更高的小版本也能编，比它低的编不了。

还需要 **Python 3**（跑构建脚本，只用标准库，不需要 `pip install` 任何东西）。

三个 csproj 都不引第三方 NuGet 包，但首次构建仍要联网从 nuget.org 取该目标框架的引用包，之后可以离线重复构建。

外加**你自己准备的宿主程序集**：游戏发行时附带的两份托管 DLL（游戏本体的编译产物，加上 Godot .NET 的脚本程序集）。本仓库不带它们，也不记录任何作者本机的路径——它们是游戏的产物，随游戏分发，版权不在本仓库。

模组是托管 C# 插件，编译期必须拿到含宿主类型定义的程序集才能通过编译。这份引用只用于编译，不会被打进 `.pmod`，运行时直接使用游戏里已经加载的那一份。第三方 mod 也都是这个形状：解包后只有清单和一份托管 DLL，DLL 引用的同样是这两份宿主程序集。

怎么把这个目录告诉构建，有三种写法，任选其一：环境变量 `PVZHOSTDIR=<目录>`（推荐，设一次长期有效，`build.py` 和三个离线工具都读它）、`python build.py --host-dir <目录>`、或给 `dotnet build` 加 `-p:PVZHostDir=<目录>`。它要指向**那两份宿主程序集所在的文件夹**：装好游戏后一般在 `<游戏安装目录>\data_PlantsVsZombies_*\` 里，`PlantsVsZombies.dll` 与 `GodotSharp.dll` 同时出现在某个目录下，指的就是那个目录。文件夹名里的平台和架构部分会随游戏版本变，拿不准就在安装目录里搜这两个文件名。没指定、或指定的目录凑不齐时，构建会带着「缺什么」直接停下，不会去猜路径。

一条龙是仓库根目录的 `build.py`，按顺序跑完编译 → 校验 → 打包 → 核对包内容，任何一步失败就停在那里：

```bash
python build.py --host-dir "<含那两份宿主程序集的目录>"   # 已设好 PVZHOSTDIR 的话不用这个参数；相对路径按仓库根目录算
python build.py --install          # 出包并装进存档 Mods\（默认不装，游戏读到的还是旧包）
python build.py --probe "<BGM 目录>"   # 额外跑一遍音频预检，可重复指定多个目录
```

**版本号一律严格 semver**（SemVer 2.0）：正式版写三段（`1.2.3`、`1.3.0`），内测按预发布标记分三档——`1.3.0-alpha.1`（还在试方向）、`1.3.0-beta.2`（功能齐了、等验证）、`1.3.0-rc.1`（没有新问题就当正式版发）。它由定版的人手写进 `mod.json` 的 `version`，打包时一个字节都不改。写成四段（`1.2.2.6`）或带上构建号都会被打包直接拦下。定新版要一起改的只有三处：`version`、「关于」页那句 `音乐盒 v<版本号>`、以及 `changelog.txt` 里新加的那一段（改完跑一次 `python .build/seed.py`，把公告正文同步进 `mod.json`）。

**构建号已经取消**：同一个版反复出包就是覆盖同一个包名（正式包叫 `MusicBox-<版本号>.pmod`，不带 ID 哈希那串后缀——防撞靠 `mod.json` 里的 `id`，文件名那八个字符对玩家没有意义）。换版本后旧包名会留在 `dist\` 和存档 `Mods\` 里，所以打包会把同前缀的旧包删掉——游戏见到两个相同 ID 的包会判「存在重复的已安装 Mod ID」，整批不加载。

`build.py` 全程不写仓库里的任何文件，所以它本身就能当流程自检用：克隆下来直接跑一遍，闸门全过就说明这台机器能构建。

默认只在 `dist/` 里出包，不碰存档目录；构建缓存（TEMP / NuGet / dotnet CLI）也都收进 `.build/` 里，不污染系统临时目录。想只跑其中一步，或者想知道每一步在干什么，照下面抄（都在仓库根目录执行）：

```bash
export TEMP="$PWD/.build/TEMP" TMP="$PWD/.build/TEMP" TMPDIR="$PWD/.build/TEMP" \
       DOTNET_CLI_HOME="$PWD/.build/tmp" NUGET_PACKAGES="$PWD/.build/tmp/nuget" \
       PVZHOSTDIR="<含那两份宿主程序集的目录>"

# 1. 编译运行时 DLL（引用宿主程序集，但不把它们拷进输出目录）
dotnet build .build/ModAssembly.csproj -c Release -o .build/bin/Release --nologo -p:UseSharedCompilation=false

# 2. 离线校验 mod.json 的 settings 声明（反射宿主面板，不用开游戏；读 PVZHOSTDIR）
dotnet run --project .build/validate -c Release -- mod.json
```

## 已知宿主限制（改动前值得先看一眼）

- 游戏读外部音频时**只按传入的扩展名选解码方式**，不看文件内容；单个文件上限 64MB，FLAC 还要求 8/16-bit、单声道或立体声、解码后不超过 128MB。模组因此自己按文件头认格式，挂错名的歌也能播，读不了的在下拉前就被拦下。
- 游戏的 Mod 配置面板只有开关、数值、文本、下拉这类普通项，没有按钮，所以面板里做不出「刷新」这类交互。面板还要求包体与启动时登记的指纹一致，模组每次启动把下拉选项重写成目录实际扫到的曲目后，本局会提示「正在使用旧版本，重启并应用」——这是预期行为。
- 从载入界面进主菜单（选关、图鉴同理）时，游戏会把同一首音乐从头重放一遍，模组拦不住这个行为，只能在下一帧把播放位置按回刚才的地方，实现续播。
- 游戏导出时裁剪了部分 .NET 运行库：标准 HTTP 客户端不能直接用，联网检查更新走的是宿主提供的请求通道；个别字符串拆分写法会绑到被裁剪的重载上，低层的字节解析也都手写避开了。
- 更新检测已同步游戏官方的统一更新接口：发现新版由游戏汇总提醒，本模组不自建弹窗。

## 更新检测渠道

面板「关于 → 检测更新渠道」三项，改动**下次启动生效**（`applyMode=restart`）：

| 选项 | 值 | 谁去查 | 说明 |
| --- | --- | --- | --- |
| 关闭 | `off` | 没人查 | 模组一条请求都不发，同时**把自己包里的 `postId` 清空**：游戏的官网检查只扫带 `postId` 的包，清掉之后它也不会替本模组去问官网。改的是包体，所以这次退出从下一次启动起成立。 |
| 官网 | `official` | 游戏 | 模组绝不查 GitHub，也绝不自己上报（本模组成功上报过一次，游戏就会忽略这个 Mod 的官网结果），包里 `postId` 保持绑着，更新结果全部由游戏的官网检查给出。 |
| Github | `github`（默认） | 模组 | 与之前「启动时检查更新」开着时完全一致：模组自己查本仓库最新的 Release，`tag_name` 当最新版、`html_url` 当下载页。**这是唯一由模组发起的网络请求，而且只连本仓库。** |

模组不连官网接口，一次都不发；要官网的结果就交给游戏自己查。切换渠道时包里 `postId` 的增删和面板项重写在同一趟里完成（启动时的声明同步），日志会写明「官网投稿绑定已清空」还是「仍绑 2」。`github` 渠道要求 Release 的 tag 是严格 semver，否则只记一条日志、不报版本号。

## 更新源

发新版就是**发一个 GitHub Release**：`github` 渠道每次启动查 `https://api.github.com/repos/NaiyxYin/PVZHE_MusicBox/releases/latest`，把返回里的 `tag_name` 当最新模组版本、`html_url`（也就是 Release 页）当下载页。仓库里不再有 `update.txt`，线上没有需要单独维护的更新文件。

- tag 写**严格 semver**：正式版就 `1.2.3`，内测就 `1.2.3-beta.1`（带 `v` 前缀也行，读取时会去掉）。不符合规范的 tag（比如写成四段 `1.2.3.0`）能被认出来，但**只记一条日志、不作提醒**：比不了大小，就不该把玩家引过去。
- 比较照 semver 规范：`1.3.0-alpha.1 < 1.3.0-beta.2 < 1.3.0-beta.10 < 1.3.0-rc.1 < 1.3.0`；`+构建元数据`按规范不参与比较，tag 也只写版本本身（构建号已取消），所以不会出现「每次打包都提示有更新」。
- 内测 Release 要在 GitHub 上勾 **pre-release**：`/releases/latest` 只返回「最新的非草稿、非预发布」那一条，内测包不会推给玩家，玩家只会收到正式版的提醒。装了内测包的人升到正式版时照样会收到提醒（正式版大于同号的任何预发布）。
- `.pmod` 传成该 Release 的**附件**（`dist/*.pmod`）；玩家点提醒里的「打开更新页面」就落到 Release 页，附件和更新说明都在那儿。内测包不用另开渠道，把 Release 页链接直接发给测试的人就行。
- 发现新版就交给宿主的统一更新提醒：游戏把所有 Mod 的更新汇总成一份，列出「模组名 · 当前版本 → 新版本」和一个「打开更新页面」按钮，模组自己不弹窗。
- 任何失败（连不上、404、返回的不是 JSON）都**只写一条日志，绝不打扰玩家**，并在 3 秒后静默重试一轮。
- 游戏只在**进主菜单后的 2 秒内**收集各 Mod 上报的更新，再根据这些结果决定要不要自动弹提醒；晚于 2 秒上报的不会自动弹，但仍留在「更新列表」里可以手动打开。网慢就是这个表现，和「没有正式版 Release」的静默不一样，日志能分清是哪种。
- 还没有正式版 Release（全都还是草稿或预发布）时这个地址返回 404，等同于「已最新」；仓库是 private 时同样 404，转 public 后自动恢复。

地址写在 `Scripts/MusicBoxUpdate.cs` 的 `UpdateFeedUrl` 里，仓库搬家或改名时要一起改；GitHub API 不给 `User-Agent` 会直接 403，所以同处的 `UpdateFeedHeaders` 也得留着。

`python .build/verify.py` 会核对这几件事：`version` 是严格 semver 且不带 `+构建元数据`；「关于」页那句正好是 `v<版本>`；包名正好是 `MusicBox-<版本>.pmod` 且没混进 ID 哈希后缀；更新源地址里没有占位（例如还没填的 `OWNER`）；地址确实是 `/releases/latest`；请求带 `User-Agent`；仓库里没有残留的 `update.txt`；`postId` 是不含前导零的数字文本且和源码里的 `OfficialPostId` 对得上；`id`/`author`/`version` 三项都过宿主新加的元数据校验（非法元数据现在整包拒载）；semver 那套实现真的编进了 DLL；以及**源码里既没有官网接口地址，也没有任何自发的 POST/反射调用**。

## 官网投稿 ID（postId）

游戏在 2026-10-15 加了一条**模组不用联网**的统一更新通道：`mod.json` 根节点声明可选字符串 `postId`，填官网对应 Mod 投稿的数字 ID（和本地 `id` 无关），游戏启动后自己向官网查一次；返回里带 `newVersion` 和 `updateInfo` 就生成提醒行。**本模组绑定的是 `"postId": "2"`。**

- 参加条件由宿主把关：包已 applied、本次没进故障表、`postId` 是不含前导零的正整数字符串、`version` 是严格 semver，任一不满足就静默不参加，不影响加载。所以 `postId` 写错（比如 `"02"`）的表现是「一直没有提醒」，而不是报错。
- 官网接口只给版本和说明，**没有下载地址**，所以它生成的提醒不带「打开更新页面」按钮。
- 自主上报的结果优先于官网结果：模组一旦成功上报过（有更新或没更新都算），宿主就忽略这个 Mod 的官网行。所以面板选「官网」时模组刻意什么都不上报，把这一行留给游戏自己生成。
- 「关闭」这一档要连游戏那次请求一起退掉，只能靠清空包里的 `postId`（模组没有运行时的退出接口），于是渠道切换的效果固定滞后一次重启。
- 旧宿主不认识 `postId`，多出来的字段只是被忽略（0.30.0 正式版还没有这条链路），所以官网那条要生效得用包含该功能的构建。

实机日志在 `存档目录\logs\godot.log`，正常启动会有一行 `[Mod:MusicBox] 运行入口已加载 v<版本>`；没有这行说明跑的还是旧包。
